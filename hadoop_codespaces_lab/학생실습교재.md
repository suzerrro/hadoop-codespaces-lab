# GitHub Codespaces 기반 Apache Hadoop 실습교재

**빅데이터플랫폼개론 | HDFS 분산 저장 · 복제 · 장애 실험 · YARN/MapReduce(심화)**  
실습 방식: 학생 PC 설치 없음 · 웹브라우저 사용 · GitHub Codespaces에서 Docker Compose 실행  
실습 분량: 기본 100분 × 2차시 / 심화 50~100분 선택  
실습 버전: Apache Hadoop `3.4.3` (공식 Docker 이미지)

---

## 1. 실습 목표와 주의사항

이 실습을 마치면 학생은 다음을 직접 확인할 수 있습니다.

1. Docker 컨테이너 3개로 NameNode 1개와 DataNode 2개를 구성한다.
2. 일반 리눅스 파일 경로와 HDFS 경로가 **서로 다른 저장 공간**임을 구분한다.
3. HDFS에 CSV 파일을 업로드하고 블록 크기·블록 수·복제본 위치를 확인한다.
4. DataNode 하나를 정지시켜도 파일을 읽을 수 있는 이유를 설명한다.
5. (선택) YARN의 ResourceManager·NodeManager를 실행하고 WordCount를 수행한다.

**중요한 제한:** NameNode와 DataNode는 서로 다른 **컨테이너**이지만, 실제로는 하나의 Codespaces 가상머신 위에서 실행됩니다. 즉, 물리적으로 분리된 컴퓨터의 장애를 재현하는 실험은 아닙니다. 또한 본 자료는 교육용으로 보안을 강화한 운영 환경이 아닙니다.

### 클러스터 구조

```text
학생 PC (브라우저만 사용)
          |
          v
GitHub Codespaces (클라우드 Linux VM)
          |
          +-- Docker Compose
                |
                +-- namenode     : NameNode     / UI 9870
                +-- datanode1    : DataNode 1   / 실제 블록 저장
                +-- datanode2    : DataNode 2   / 복제 블록 저장
                |
                +-- (선택) resourcemanager : YARN / UI 8088
                +-- (선택) nodemanager     : YARN 실행 노드
```

### 권장 환경

- GitHub 계정, Chromium 기반 브라우저 등 일반 웹브라우저.
- Codespaces의 **2코어·8GB**는 기본 HDFS 실습을 우선 시도할 수 있는 사양입니다.
- WordCount 등 YARN 심화 단계는 **4코어·16GB**가 더 안정적입니다. 사용량·과금 정책은 계정별 확인이 필요합니다.
- 별도 Docker Desktop, Java, Hadoop을 학생 PC에 설치하지 않습니다.
- **지난 Spark 저장소를 수정하지 않고, Hadoop용 신규 저장소**를 만듭니다.
- **`.devcontainer` 폴더를 만들지 않습니다.** 이전 Spark 실습에서 devcontainer 기능 빌드 실패가 있었으므로 GitHub 기본 Codespaces 설정을 먼저 사용합니다.

## 2. 실습 0 — GitHub 저장소 생성 및 업로드

### STEP 0-1. 새 저장소 만들기

1. GitHub에 로그인합니다.
2. GitHub 화면 오른쪽 위의 `+` 버튼을 누르고 **New repository**를 선택합니다.
3. `Repository name`에 **`hadoop-codespaces-lab`**를 입력합니다.
4. `Visibility`는 **Public**, `Add README`는 **Off**로 설정합니다.
5. `Create repository`를 클릭합니다.

### STEP 0-2. 실습 파일 업로드

1. 교수자가 배포한 `hadoop_codespaces_lab.zip`을 PC에 다운로드해 **압축 해제**합니다.
2. 방금 만든 빈 저장소 화면의 파란색 `Quick setup`에서 **uploading an existing file**을 클릭합니다.
3. 압축을 푼 폴더 **안쪽의 파일·폴더**를 업로드 창으로 끌어다 놓습니다. ZIP만 업로드하거나 상위 폴더째 한 겹 더 넣지 마세요.
4. 맨 아래 `Commit changes`를 눌러 업로드를 완료합니다.
5. 저장소 루트에서 `docker-compose.yml`, `hadoop.env`, `data`, `scripts`가 보이는지 확인합니다.

**구조 확인:** `docker-compose.yml` 파일이 저장소 최상위에 있어야 합니다. `.devcontainer`는 **없어야 정상**입니다.

### STEP 0-3. Codespaces 열기

1. 저장소의 **Code** 탭에서 파일 목록 위쪽의 초록색 **Code** 버튼을 누릅니다.
2. 팝업에서 **Codespaces** 탭을 누릅니다.
3. **Create codespace on main**을 누릅니다.
4. 웹 VS Code 화면이 열리면 상단 메뉴 **Terminal → New Terminal**을 선택합니다.

실습 중 화면 아래 패널의 **터미널(Terminal)**에 명령을 입력합니다. GitHub 웹사이트의 검색창에 입력하는 것이 아닙니다.

### 확인 질문 0

**Q.** 학생 PC에 Hadoop을 설치하지 않았는데 Hadoop을 실행할 수 있는 이유는 무엇인가요?  
**A.** 프로그램이 학생 PC가 아니라 GitHub가 제공하는 원격 Linux VM의 컨테이너에서 실행되기 때문입니다.

## 3. 실습 1 — Docker 실행 준비와 HDFS 클러스터 구성

### STEP 1-1. 프로젝트 경로 확인

Codespaces 터미널에서 실행:

```bash
pwd
ls -la
```

확인: 현재 작업 폴더에 `docker-compose.yml`, `hadoop.env`, `data/`, `scripts/`가 보여야 합니다. `pwd`는 현재 폴더의 절대 경로를 보여줍니다.

### STEP 1-2. Docker가 정상인지 확인

```bash
docker --version
docker compose version
docker info
```

- `docker --version`: Docker **명령행 도구**의 버전을 보여줍니다.
- `docker compose version`: 여러 서비스를 함께 구성하는 Compose 플러그인을 확인합니다.
- `docker info`: **실제 Docker 데몬과 연결되는지** 확인합니다. 설치되었더라도 데몬에 연결되지 않으면 실패합니다.

**중요:** `docker: command not found`가 표시되면 Docker를 학생 PC에 설치하지 마세요. Codespaces가 Recovery Mode인지, 혹은 이전 Spark 저장소에서 오류가 발생한 환경을 다시 사용한 것은 아닌지 확인해야 합니다. 이 교재는 새 저장소의 **기본 Codespaces 환경**을 전제로 합니다.

### STEP 1-3. 클러스터 실행

```bash
bash scripts/start_hdfs.sh
```

이 스크립트는 다음을 순서대로 수행합니다.

1. Apache 공식 Hadoop Docker 이미지 `apache/hadoop:3.4.3`를 가져옵니다.
2. NameNode 1개 + DataNode 2개를 실행합니다.
3. NameNode가 보고하는 `Live datanodes (2)` 상태를 확인합니다.

학생이 각각 명령으로 실행하려면 다음과 같습니다.

```bash
docker compose pull
docker compose up -d namenode datanode1 datanode2
docker compose ps
bash scripts/check_cluster.sh
```

`docker compose ps`에서 세 서비스가 `Up` 또는 `running` 상태인지 확인합니다. 단순히 컨테이너가 실행 중인 것과 **HDFS DataNode 등록까지 끝난 것**은 서로 다릅니다.

### STEP 1-4. NameNode에서 노드 상태 확인

```bash
docker compose exec namenode hdfs dfsadmin -report
```

핵심적으로 확인할 내용:

```text
Live datanodes (2):
```

**예상값:** 정상 상태에서는 2가 나옵니다. `Configured Capacity`, `DFS Used`, `DFS Remaining` 등은 환경마다 다릅니다.

### STEP 1-5. NameNode Web UI 보기

1. Codespaces 화면 아래의 **포트(Ports)** 탭을 클릭합니다.
2. 포트 목록에서 **9870**을 찾습니다.
3. 해당 포트의 **Open in Browser / 지구본 아이콘**을 클릭합니다.
4. **Overview → Datanodes** 등 메뉴에서 두 노드의 상태를 확인합니다.

Codespaces에서 제공하는 **포트 연결 URL**을 이용하세요. 자기 PC의 `localhost:9870`을 임의로 입력할 필요가 없습니다. 공유·실습 환경에서는 포트 공개 설정을 **Private**로 유지하세요.

### 확인 질문 1

- NameNode는 파일의 내용 전체를 저장하나요, 블록 위치 등 메타데이터를 관리하나요?
- DataNode 컨테이너 2개를 만들었는데, DataNode가 물리적으로도 서로 다른 컴퓨터에 있나요?

## 4. 실습 2 — 로컬 파일과 HDFS 파일의 차이

### STEP 2-1. 로컬 데이터 확인

Codespaces 터미널:

```bash
ls -lh data/
head -n 5 data/orders.csv
wc -l data/orders.csv
cat data/words.txt
```

**예상:** `orders.csv`는 헤더 1행 + 주문 데이터 120,000행, 합계 **120,001행**입니다. 데이터는 주문번호, 주문일, 도시, 상품, 금액, 상태로 구성됩니다.

여기서 `data/orders.csv`는 **Codespaces 개발환경의 일반 파일**이지, HDFS에 들어간 데이터가 아닙니다.

### STEP 2-2. 데이터를 HDFS로 업로드

```bash
bash scripts/load_data.sh
```

내부적으로 일어나는 작업:

```bash
# (1) Codespaces → NameNode 컨테이너의 /tmp로 복사
docker compose cp data/orders.csv namenode:/tmp/orders.csv

# (2) NameNode 컨테이너에서 HDFS 폴더 생성
docker compose exec namenode hdfs dfs -mkdir -p /lab/input

# (3) NameNode 컨테이너에서 HDFS로 파일 업로드
docker compose exec namenode hdfs dfs -put -f /tmp/orders.csv /lab/input/orders.csv
```

**두 번의 이동을 구분하세요.** `docker compose cp`는 **컨테이너 파일 시스템**으로 복사하고, `hdfs dfs -put`은 **HDFS 분산 파일 시스템**에 기록합니다. 메타데이터는 NameNode가, 파일 블록은 DataNode가 담당합니다.

### STEP 2-3. HDFS 목록 확인

```bash
docker compose exec namenode hdfs dfs -ls -h /lab/input
```

예상 파일:

```text
/lab/input/orders.csv
/lab/input/words.txt
```

### STEP 2-4. HDFS 파일 내용 읽기

```bash
docker compose exec namenode hdfs dfs -cat /lab/input/words.txt
docker compose exec namenode hdfs dfs -head /lab/input/orders.csv
```

`-head`는 파일의 **시작 부분만** 확인하는 명령입니다. 대형 파일을 전부 출력하지 않기 위해 사용합니다.

### STEP 2-5. HDFS에서 컨테이너로 가져오기

```bash
docker compose exec namenode hdfs dfs -get -f /lab/input/words.txt /tmp/words_downloaded.txt
docker compose exec namenode cat /tmp/words_downloaded.txt
```

`-get`은 HDFS에서 **명령을 실행 중인 컨테이너의 로컬 파일 시스템**으로 내려받습니다. 현재 PC로 직접 다운로드한 것은 아닙니다.

### 확인 질문 2

**Q.** `docker compose cp`와 `hdfs dfs -put`의 차이는 무엇인가요?  
**A.** 첫 번째는 파일을 특정 컨테이너의 경로에 복사합니다. 두 번째는 HDFS 클라이언트가 파일을 블록으로 나누어 DataNode에 저장하도록 요청합니다.

## 5. 실습 3 — HDFS 블록 분할과 복제 확인

### STEP 3-1. 파일 크기, 블록 크기, 복제 계수 확인

```bash
docker compose exec namenode hdfs dfs -stat '%n %b %o %r' /lab/input/orders.csv
```

표시 순서: `파일명 파일크기(바이트) 블록크기(바이트) 복제계수`.

실습 설정은 아래와 같습니다.

| 항목 | 값 | 의미 |
|---|---:|---|
| `dfs.blocksize` | 1,048,576B (1MiB) | 학습용 작은 HDFS 블록 크기 |
| `dfs.replication` | 2 | 블록을 DataNode 2곳에 복제 |
| `orders.csv` | 약 5.8MB | 약 6개의 블록으로 분할될 것으로 예상 |

실제 블록 수는 파일의 바이트 크기와 생성 시 적용된 블록 크기에 따라 달라집니다.

### STEP 3-2. 블록과 실제 저장 위치 확인

```bash
docker compose exec namenode hdfs fsck /lab/input/orders.csv -files -blocks -locations
```

출력에서 다음을 찾습니다.

- `Total blocks` 또는 파일 아래의 `blk_...` 줄: 블록 식별자와 수
- 각 블록의 `repl=2`: 목표 복제 계수
- 각 블록의 위치: 서로 다른 DataNode의 IP 또는 호스트
- 상태 `HEALTHY`: HDFS에서 문제가 발견되지 않음

**주요 개념:** HDFS는 중앙으로 모든 파일을 모아서 보관하는 구조가 아닙니다. NameNode는 블록 메타데이터를 관리하고, DataNode 두 개가 실제 데이터를 보관합니다.

### STEP 3-3. 실제 블록 수 추정하기

```bash
python3 - <<'PY'
import math, os
size = os.path.getsize('data/orders.csv')
block = 1024 * 1024
print('파일 크기(bytes):', size)
print('블록 크기(bytes):', block)
print('예상 HDFS 블록 수:', math.ceil(size / block))
print('예상 블록 복제본 수:', 2 * math.ceil(size / block))
PY
```

**참고:** 위 계산은 일반적인 파일 블록 개수의 예상치입니다. `fsck`에서 실제 블록 수와 복제본 상태를 확인해야 합니다. 빈 파일, 처리 중인 파일, 장애 상황에서는 단순 계산과 다를 수 있습니다.

### 확인 질문 3

- 5.8MB 파일을 1MiB 블록으로 나누면 왜 약 6개인가요?
- 복제 계수 2일 때 데이터가 두 배 저장되더라도, 학생이 `hdfs dfs -cat`으로 읽을 때 같은 문장이 두 번 보이지 않는 이유는 무엇인가요?

## 6. 실습 4 — DataNode 장애와 복제의 효과

**주의:** 이 실험은 오직 본인의 교육용 Codespaces에서만 실행합니다. 공유 운영 서버나 다른 학생의 서버에서는 실행하지 않습니다.

### STEP 4-1. 실험 직전 정상 상태 기록

```bash
docker compose exec namenode hdfs dfsadmin -report
docker compose exec namenode hdfs fsck /lab/input/orders.csv -files -blocks -locations
```

기록 항목: `Live datanodes`, `Dead datanodes`, 블록 복제본 위치.

### STEP 4-2. 두 번째 DataNode 정지

```bash
docker compose stop datanode2
```

Docker가 `datanode2` 컨테이너를 정지합니다. **NameNode 컨테이너는 그대로**입니다.

### STEP 4-3. DataNode 상태 변화 확인

```bash
docker compose exec namenode hdfs dfsadmin -report
```

장애 감지에는 시간이 걸립니다. 상태 갱신 후 `Live datanodes (1)` 등으로 변하는지 확인하세요. 아직 2로 보이면 서버가 장애를 인식하는 과정을 관찰하고, 로그를 확인하세요.

### STEP 4-4. 같은 파일을 다시 읽기

```bash
docker compose exec namenode hdfs dfs -head /lab/input/orders.csv
```

**예상:** 첫 번째 DataNode에 동일 블록의 복제본이 남아 있다면 파일을 계속 읽을 수 있습니다. 이는 복제 계수 2의 효과입니다. 반면, 복제 상태는 부족해지므로 클러스터의 내결함성이 감소합니다.

### STEP 4-5. 복제 상태 점검

```bash
docker compose exec namenode hdfs fsck /lab/input/orders.csv -files -blocks -locations
```

`Under replicated` 또는 블록 복제본 수 감소 등의 메시지가 나타날 수 있습니다. **파일을 읽을 수 있다**는 것과 **정상 복제 상태를 유지한다**는 것은 다릅니다.

### STEP 4-6. DataNode 복구

```bash
docker compose start datanode2
bash scripts/check_cluster.sh
```

다시 DataNode 2개가 등록되는지 확인하고 `fsck`를 재실행하세요.

### 확인 질문 4

- NameNode가 정지했을 때와 DataNode 하나가 정지했을 때 현상이 왜 다른가요?
- 복제 계수가 1이었다면 동일한 장애에서 어떤 위험이 있을까요?
- 두 DataNode가 **같은 물리 VM** 위에 있다는 한계는 무엇일까요?

### STEP 5-5. 파일 삭제하기

```bash
docker compose exec namenode hdfs dfs -rm /lab/archive/words_2026.txt
```

**응용:** 리눅스 `cp`, `mv`, `rm`과 기능이 비슷해 보여도 HDFS 명령은 **`hdfs dfs`를 붙여야** 하며 HDFS 경로에 작동합니다.

## 8. 실습 6 — YARN과 Hadoop MapReduce (선택 심화)

이 실습은 기본 HDFS에 YARN 서비스 두 개를 **추가**합니다. 4코어·16GB Codespaces를 권장합니다. 먼저 HDFS 실습 1~5가 정상 작동하는지 확인하세요.

### MapReduce 클러스터 구조

```text
Input file (HDFS: /lab/input/words.txt)
                  |
                  v
          YARN ResourceManager
                  |
                  v
           YARN NodeManager
                  |
                  v
        Map → Shuffle/Sort → Reduce
                  |
                  v
Output file (HDFS: /lab/output/wordcount)
```

### STEP 6-1. ResourceManager·NodeManager 실행

```bash
docker compose --profile mapreduce up -d resourcemanager nodemanager
docker compose --profile mapreduce ps
```

### STEP 6-2. YARN 노드 등록 확인

```bash
docker compose exec resourcemanager yarn node -list
```

정상 연결되었다면 `Total Nodes:1`과 비슷한 형태로 NodeManager 한 대가 표시됩니다. 이 예제에서 HDFS DataNode는 2개이지만 **YARN NodeManager는 1개**입니다. 저장 노드 수와 계산 노드 수가 같을 필요는 없습니다.

### STEP 6-3. WordCount 실행

```bash
bash scripts/run_wordcount.sh
```

스크립트는 YARN을 시작하고 실행 노드를 확인한 뒤, Hadoop의 공식 예제 JAR에서 `wordcount` 작업을 실행합니다. 출력 디렉터리가 기존에 있으면 작업이 실패하므로 이전 결과를 먼저 삭제합니다.

### STEP 6-4. WordCount 결과 확인

```bash
docker compose exec namenode hdfs dfs -cat /lab/output/wordcount/part-r-00000
```

데이터 `words.txt`가 원본 그대로라면 아래와 같은 빈도가 나옵니다(출력 순서는 다를 수 있음).

```text
data        5
datanode    1
hadoop      5
hdfs        3
namenode    1
spark       3
```

**주의:** 이 실습에서 사용한 것은 Hadoop Java MapReduce 예제입니다. Spark의 `RDD.map` 코드를 실행한 것은 아닙니다.

### STEP 6-5. YARN Web UI 확인

Codespaces **포트(Ports)** 탭에서 **8088**을 열고 실행된 Application의 상태를 확인합니다. 이 환경은 교육용으로 한 VM에서 실행되기 때문에 실제 다수 물리 서버 환경과 자원 격리는 다릅니다.

### 확인 질문 6

- HDFS NameNode와 YARN ResourceManager의 역할은 어떻게 다른가요?
- Map에서 출력한 `(단어, 1)` 쌍이 Shuffle/Sort를 거쳐 Reduce에서 어떻게 집계되나요?
- MapReduce 실행 결과를 어디에 저장했나요? (일반 파일 경로인가요, HDFS인가요?)

## 9. 실습 7 — 강제 초기화·복구·종료

### STEP 7-1. 비용과 리소스 낭비 없이 서비스 정지

```bash
docker compose --profile mapreduce stop
```

이 명령은 컨테이너를 **중지하지만 삭제하지는 않습니다.** 다시 시작할 때:

```bash
docker compose --profile mapreduce start
```

### STEP 7-2. 실습 환경을 완전히 초기화해야 할 때

```bash
bash scripts/reset_all.sh
```

화면에 나타나는 안내에 따라 `RESET`을 입력하면 컨테이너가 삭제됩니다. **컨테이너 내부 HDFS 실습 데이터도 삭제됩니다.** 중요한 데이터는 먼저 `hdfs dfs -get`으로 보존하세요.

### STEP 7-3. Codespaces 종료

GitHub의 Codespaces 관리 화면에서 **Stop codespace**로 원격 개발환경을 중지합니다. **컨테이너 중지와 Codespaces VM 중지**는 별개의 단계입니다. Codespaces 사용량과 계정 과금 정책을 확인하세요.

## 10. 오류 메시지별 대처

| 오류/증상 | 가장 먼저 할 일 | 흔한 원인 |
|---|---|---|
| `docker: command not found` | 현재 Codespaces가 Recovery Mode인지 확인 | 개발 컨테이너 생성 실패 또는 잘못된 환경 사용 |
| `Cannot connect to the Docker daemon` | `docker info` 확인 | 도커 데몬 접근 불가 |
| `no configuration file provided` | `pwd`, `ls` 확인 | 저장소 루트가 아닌 다른 폴더에서 실행 |
| NameNode Web UI 안 열림 | `docker compose ps`, 포트 `9870` 확인 | NameNode 컨테이너 비정상 또는 포트 연결 누락 |
| `Live datanodes (0)` | `docker compose logs datanode1 datanode2` 확인 | DataNode 등록 지연 또는 컨테이너 오류 |
| `SafeModeException` | `hdfs dfsadmin -safemode get` 및 복제 상태 확인 | 초기 준비 또는 클러스터 문제 |
| `No such file or directory` | `hdfs dfs -ls /lab/input` | 경로 오타 또는 업로드 이전 단계 누락 |
| MapReduce `FileAlreadyExistsException` | WordCount 출력 디렉터리 삭제 | MapReduce는 기존 출력 경로에 덮어쓰지 않음 |
| YARN 메모리 오류 | Codespaces 사양 확대 또는 심화 생략 | 5개 컨테이너의 메모리 부족 |

**오류 진단 시 추천 명령:**

```bash
docker compose ps
docker compose logs --tail=60 namenode datanode1 datanode2
docker compose exec namenode hdfs dfsadmin -report
```

**주의:** 오류를 해결하기 위해 `hdfs namenode -format`을 반복 실행하면 기존 메타데이터가 손실될 수 있습니다. 이 자료의 자동 시작 스크립트와 초기화 스크립트를 구분해 사용하세요.

docker --version && docker compose version && docker info
